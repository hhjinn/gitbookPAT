### During installation `Error: Environment variable 'OPENSQL_HOME' is not set.` if the following is displayed

The environment variables required by the installation script are not set. `OPENSQL_HOME`, `PG_HOME`, `PG_DATA_DIR` Set the three values and run it again.

```bash
export OPENSQL_HOME=/opt/postgresql
export PG_HOME=/opt/postgresql
export PG_DATA_DIR=/opt/postgresql/data
```

The OwlDB Agent is not registered with the OwlDB server.

```bash
systemctl is-active owldb-barman-agent.service owldb-barman-agent.timer
cat /var/lib/barman/owlagent_dist/owlagent.env
```

`AGENT_TYPE` If `barman` whether it is, `IP` and `PORT` Check whether it matches the OwlDB server address. If you modified it, `owlagent_stop.sh` stop it with `owlagent_start.sh` and run it again.

`barman` There is no NOPASSWD sudo setting for the account.

### During integration `barman-wal-archive` If it fails with an error that it does not exist

Set the WAL retention method `archiver` or `archiver+streaming` You selected it, but on the database server `barman-cli` is not installed. Refer to 1-2 to install it.

### If Health is displayed as Not Connected

`barman check` Among the items, **WAL archive** and **continuous archiving** if it fails, Health is displayed as Not Connected. WAL is not being transmitted from the database server to the Barman server.

Check the failed item on the OpenBackup server.

```bash
su - barman
barman check <database ID>
```

`WAL archive: FAILED` or `continuous archiving: FAILED` If the following is displayed, check whether the database server can connect to the OpenBackup server. **With the OpenSQL account on the database server,** run it.

```bash
ssh -o BatchMode=yes -i <node registration key> barman@<Barman server IP> hostname
```

| Output | Cause and action |
| --- | --- |
| `Permission denied (publickey)` | The OpenBackup server does not allow this key. **OpenBackup** **Server installation** In document 7-1, `authorized_keys` check the registration |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | The database server remembers the host key of the previous OpenBackup server. Refer to the item below. |
| OpenBackup server hostname | This direction is normal. Also check the reverse direction below. |

Also check the reverse direction (OpenBackup server → database server). This direction `barman check` of `ssh` corresponds to the item.

```bash
su - barman
ssh -o BatchMode=yes <OpenSQL account>@<database server IP> hostname
```

If it does not connect, check whether the private key file path `owlagent.env` of `BARMAN_SSH_KEYPATH` is the same as, and whether the database server allows that key.

### If Health is displayed as Not Connected after rebuilding the OpenBackup server

The database server remembers the host key of the previous OpenBackup server and refuses the connection. This occurs when the OpenBackup server is reinstalled with the same IP.

When you attempt a connection from the database server, the following is displayed.

```bash
WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!
Host key verification failed.
```

**On all database nodes,** remove the relevant item and then integrate again.

```bash
ssh-keygen -R <Barman server IP>
```

The connection configuration generated by OwlDB automatically accepts only the host key of the server it connects to for the first time, so when the host key **has changed,** you must clean it up directly as shown above.

### If WAL is not collected and the log shows `pg_receivewal not present in $PATH` if the following is displayed

`/etc/barman.conf` in `path_prefix` is not set. Set it to the path of the PostgreSQL client executable. Since cron re-reads the configuration file each time, you do not need to restart the service.

```bash
[barman]
path_prefix = /opt/postgresql/bin
```

### When a Barman version-related error occurs during backup

The OpenBackup server's `barman` and the database server's `barman-cli` versions differ. Verify that both are `3.11.1` .

```bash
# Barman server
barman --version

# Database server
rpm -q barman-cli
```
