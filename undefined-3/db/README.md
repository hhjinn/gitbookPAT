# 탐색 프로세스

OwlDB 화면에서 **탐색** 버튼을 클릭하면, OwlDB Agent가 설치된 고객 인프라의 구성 정보를 자동으로 수집하여 대시보드에서 현황을 파악할 수 있습니다.

1. **OwlDB 콘솔 화면** > **대시보드**로 이동합니다.
2. 탐색 버튼을 클릭합니다.
3. 탐색 결과는 총 4가지 항목으로 조회되며, 각 항목에 대한 상세 내용은 아래 **탐색 결과** 섹션을 참고합니다.
4. 결과를 확인하고, 각 항목에 맞는 후속 작업을 진행합니다.

{% hint style="info" %}
**참고**

데이터베이스 탐색 기능은 Root 계정에서만 사용 가능합니다.
{% endhint %}

## **설치 가능 호스트 조회**

데이터베이스를 설치할 수 있는 호스트 목록을 확인할 수 있습니다. Tibero, OpenSQL 등 엔진별로 별도의 카드로 구분되어 표시되며, 탐색 과정에서 발견되지 않은 엔진의 호스트는 카드로 표시되지 않습니다. 설치 가능 호스트 항목은 조회 전용이며, 별도의 후속 작업이 필요하지 않습니다.

| 항목 | 설명 |
| --- | --- |
| Hostname | 설치 가능 호스트 이름 |
| CPU | 호스트 CPU 정보 |
| Memory | 호스트 Memory 정보 |
| OS | 호스트 OS 정보 |

---

## **등록 가능한 데이터베이스**

고객 환경에 이미 운영 중인 데이터베이스를 자동으로 탐색하여 목록으로 제공합니다. 목록에서 원하는 데이터베이스를 선택하고 **등록** 버튼을 클릭하여 등록 과정을 진행할 수 있습니다.

| 컬럼 | 설명 |
| --- | --- |
| 데이터베이스명 | 탐색된 클러스터명 |
| 엔진 | 데이터베이스 엔진 유형 |
| 구성 정보 | 노드 수, 역할 등 기본 구성 정보 |
| 액션 | 등록 버튼 |

## 변경 감지

OwlDB에 등록된 데이터베이스가 OwlDB 외부에서 직접 변경된 경우, 변경 내역을 감지하여 알립니다.

변경 감지는 다음 두 가지 유형의 변경을 감지합니다.

| 유형 | 설명 | 예시 | 후속 작업 |
| --- | --- | --- | --- |
| **스펙 변경** | 데이터베이스의 구성 정보가 변경된 경우 | 노드 수 증가/감소 | **스펙 변경** 버튼 클릭 후 변경 내역 반영 |
| **상태 변경** | DR 구성에서 노드의 역할이 변경된 경우 | Primary ↔ Standby 역할 전환 | **상태 변경** 버튼 클릭 후 변경 내역 반영 |

카드뷰 표시 규칙은 변경 유형에 따라 다릅니다.

- **상태 변경**: 변경 사항을 적용하기 전까지 카드에는 OwlDB에 저장된 기존 상태가 그대로 표시됩니다.
- **스펙 변경**: Scale-in된 인스턴스는 카드에 표시되지 않으며, Scale-out된 인스턴스는 목록 하단에 추가로 표시됩니다.

**상태 변경** 버튼을 클릭하면 변경 전후를 비교하는 모달이 나타납니다.

- **Current(좌측)**: OwlDB에 저장된 기존 상태
- **Updated(우측)**: 탐색을 통해 감지된 현재 상태 (단, Eventlog·Status·Health·CPU·Memory·Active Session 등 상세 정보는 표시되지 않습니다.)

모달에서 **적용**을 클릭하면 상태 변경 내역이 OwlDB에 반영되고, **스펙 변경으로 이동**을 클릭하면 상태 변경 반영 후 스펙 변경 페이지로 이동합니다.

{% hint style="info" %}
**참고**

- **OwlDB를 통해 설치된 데이터베이스는 변경 감지 대상에서 제외됩니다.**
- 스펙 변경과 상태 변경이 동시에 감지된 경우, 상태 변경이 우선으로 처리됩니다.
- 모달에서 상태 변경만 적용한 경우 스펙 변경 후속 작업은 화면에서 사라지며, 반영되지 않은 스펙 변경 사항이 남아있으면 재탐색 시 다시 스펙 변경 대상으로 표시됩니다.
{% endhint %}

{% hint style="warning" %}
**주의**

토폴로지 변경이 감지된 경우 변경 감지에서 지원하지 않는 대상으로 처리되어 반영 기능이 제공되지 않습니다.
{% endhint %}

## 비정상 노드

탐색 과정에서 OwlDB가 구성 정보를 정상적으로 파악하지 못한 노드는 비정상 노드로 표시됩니다.

비정상 노드 카드에는 아래 정보가 표시됩니다.

| 항목 | 설명 |
| --- | --- |
| 노드 식별자 | 비정상으로 분류된 노드 또는 노드 그룹 식별값 |
| 비정상 유형 | 구성 파악 불가 / 부분 파악 |
| 설명 | 비정상으로 분류된 사유 |
| 가이드 | 처리 가이드 링크 또는 버튼 |

비정상 노드는 아래 두 가지 경우에 발생합니다.

| 케이스 | 설명 |
| --- | --- |
| DB 구성 파악이 전혀 안 되는 경우 | 해당 노드 1개를 비정상 노드로 표시 |
| DB 구성이 부분적으로만 파악된 경우 | 파악된 노드들을 하나의 비정상 노드로 묶어 표시 |

비정상 노드가 발생한 경우 별도의 처리 가이드를 참고하여 조치합니다.
