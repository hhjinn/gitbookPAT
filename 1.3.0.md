# New Features

### On-Premise Environment Support

Newly supports using OwlDB in an On-Premise environment.
Database deployment and operational management are possible even within the customer's internal infrastructure environment.



### Database Registration and Installation

**Database Registration**

You can register and manage an existing Tibero in operation with OwlDB.
For registered databases, you can use operational features such as status inquiry, parameter management, and backup/recovery in the same way from the OwlDB console.

**Database Installation**

Supports an automatic installation feature so that Tibero can be newly deployed in an On-Premise environment.
When you enter the required configuration information during the installation process, everything from database creation to initial setup is performed at once, allowing you to quickly configure a standardized architecture-based operational environment.



### Change Detection

Through the change detection feature, you can identify database status changes and spec changes that occurred outside of OwlDB, and apply the changed configuration information to OwlDB.



### Account and Permission Management

**Account Management**

Added a feature to create and manage user accounts.

You can set access and usage permissions for databases managed by OwlDB on a per-account basis.

**Permission Management**

You can control feature access based on the Root and Member permission system.
Depending on the permission, the execution of major tasks such as database creation and deletion is restricted.

- Root: Administrator permission that can perform database operations and major management tasks
- Member: General user permission that can query assigned databases and use limited operational features



### Failback

Added a Failback feature that can restore the operational environment switched after Failover to its original configuration.
After failover, the Primary and Standby roles are reorganized, allowing the service operational configuration to be restored to a normal state.

# **Changes**

## Feature Improvements

### Backup/Recovery

**RMGR-based Backup Support**

Supports RMGR-based backup feature in the On-Premise environment.

- Cloud Environment: CSP Snapshot-based
- On-Premise Environment: RMGR-based

By applying the backup method appropriate for the environment, backup management suitable for the database operational environment is possible.

**Backup Scheduler**

You can configure Full Backup and Incremental Backup separately in the backup scheduler.

- You can configure backup policies suitable for the operational environment by setting the execution cycle and retention period for each backup type.
- Full Backup: Performs a backup based on all data.
- Incremental Backup: Performs a backup based on data changed since the previous backup.

**Backup Chain Management**

In the backup list, you can view the relationship between Full Backup and Incremental Backup on a per-chain basis. Incremental Backup is managed in association with the Full Backup that serves as its baseline.



## Removed Features

### Backup Scheduler

**Removal of the 'Auto Retention' Setting Feature**

The auto retention setting feature has been removed to prevent backup files from accumulating unnecessarily.
