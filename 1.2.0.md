> ### **Release Highlights**
> 
> - Support for Disaster Recovery (DR) configuration and Auto Failover feature provided
> - Added storage Auto Scaling feature
> - OwlDB service automatic update
> - Improved dashboard status values and added card view

# New Features

### General

**Dark Mode Support**

Dark mode can now be used according to the user's environment settings, providing visual comfort.

**HTTPS Applied**

The security of the service has been strengthened by applying the HTTPS protocol and domain name.

### 

### **OwlDB Service Update**

Improved service continuity by adding a feature that instantly updates OwlDB without rebuilding when a new version is released.



### Database Creation

**Verify Rocky Subscription (AWS Only)**

&nbsp;Added a procedure to verify Rocky subscription status in advance, before entering the database creation page.

**Added 'Disaster Recovery (hereinafter DR) Configuration' Step**

- Newly supports DR configuration in addition to the existing Single and TAC configurations.
- You can select whether to use Auto Failover and the automation level.

**Added 'Availability Zone (hereinafter AZ) Configuration' Step**

- You can directly select the AZ of the database node to be created.
- When using DR configuration, high availability is supported through a Multi-AZ configuration.

**Storage Auto Scaling Settings**

Added a feature that automatically expands storage when storage usage reaches a threshold, supporting stable service operation.

- You can select whether to use the Storage Auto Scaling feature.
- When storage usage reaches the configured threshold, storage is automatically expanded by 10% of the existing capacity.
- To prevent excessive expansion and cost, you can set a maximum storage capacity limit.

** OS Timezone Settings**

Added a feature to set the OS timezone where the database is installed. (This affects SQL results such as sysdate, systimestamp, etc.)



### Spec Change

**TAC Scale In/Out**

Added a feature to manually scale computing resources up/down when using TAC configuration.

**DR Configuration Change**

- You can add a DR configuration to a Single or TAC configuration.
- You can change/remove the DR configuration in Single+DR and TAC+DR configurations.

# **Changes**

## Feature Improvements

### Dashboard

**Status Value Improvement**

Redefined the existing three statuses (operational status, instance status, cluster tool status) into two status values (Health, Status), providing users with more intuitive status information.

**List View Improvement**

Improved the list view to support Depth, allowing detailed inquiry of not only database information but also instance information.



### Backup/Recovery

**Automatic Application of Data File Changes**

Improved the feature so that if a Data File is added between the backup point and the recovery point, the Data File is automatically created during the recovery process.

**Snapshot Recovery Option Expansion**

Added a full recovery option in addition to the PITR (Point In Time Recovery) option for snapshot recovery.



## Usability Improvements

### General

**Action Button Adjustment**

Improved readability by grouping buttons with similar properties among the previously listed buttons.

**Table Column Adjustment**

Added a feature to change the order of columns displayed in the table or to enable/disable them.



### Dashboard

**Card View Addition**

Increased the speed of grasping information by adding a card view type that allows you to concisely check only important information.



### Database Creation

**BYOL License Upload Location Change**

Changed the BYOL license file upload location from the 'Engine Options' step to the 'Configuration Verification' step, improving it so that the license matching the final configuration can be accurately applied following an intuitive flow after all settings are complete.

**Maximum vCPU Option Expansion**

Expanded the EC2/VM type options to allow selection of up to 96 vCPUs.

**Automatic Calculation of Redo Log Volume Size**

Changed the Redo Log Volume Size to use an automatically calculated value instead of being set directly by the user.

**Listener Port Input Location Change**

Simplified the procedure by changing the Listener Port input item from the deleted 'Network Configuration' step to the additional configuration in the 'Database Configuration' step.

**Simplified DB User Creation**

Simplified the procedure by changing it to only require entering the SYS user's password instead of creating a new DBA user.



## Deletion Information

### Database Creation

**Deletion of 'Network Configuration' Step**

Deleted the 'Network Configuration' step as VPC (VNet) and Subnet information was determined to be unnecessary.
