# 1.2.0

> #### **Release Highlights**
>
> * Support for Disaster Recovery (DR) configuration and the Auto Failover feature
> * Added Storage Auto Scaling
> * Automatic OwlDB service updates
> * Improved dashboard status values and added card view

## New Features

#### General

**Dark Mode Support**

Dark mode now follows the user's environment settings, providing a more comfortable viewing experience.

**HTTPS Applied**

Applied HTTPS and a domain name to strengthen service security.

#### **OwlDB Service Update**

Added a feature to instantly update OwlDB without rebuilding when a new version is released. This improves service continuity.

#### Database Creation

**Checking Rocky Subscription Status (AWS Only)**

Added a procedure to verify the Rocky subscription status before opening the database creation page.

**Added the 'Disaster Recovery (hereinafter DR) Configuration' Step**

* In addition to the existing Single and TAC configurations, DR configuration is now supported.
* You can select whether to use Auto Failover and the level of automation.

**Added the 'Availability Zone (hereinafter AZ) Configuration' Step**

* You can select the AZ directly for the database node being created.
* When using DR configuration, high availability is supported through Multi-AZ configuration.

**Storage Auto Scaling Settings**

Added a feature that automatically expands storage when usage reaches a threshold, supporting stable service operation.

* You can select whether to use the Storage Auto Scaling feature.
* When storage usage reaches the configured threshold, storage is automatically expanded by 10% of the existing capacity.
* To prevent excessive expansion and costs, you can set a maximum storage capacity limit.

**OS Timezone Settings**

Added a feature to set the OS timezone where the database is installed. It affects SQL results such as `sysdate` and `systimestamp`.

#### Spec Change

**TAC Scale In/Out**

Added a feature to manually scale computing resources up or down when using TAC configuration.

**DR Configuration Change**

* You can add a DR configuration to Single and TAC configurations.
* You can change or remove the DR configuration in Single+DR and TAC+DR configurations.

***

## **Changes**

### Feature Improvements

#### Dashboard

**Status Value Improvement**

Replaced the existing three statuses (operation, instance, and cluster tool status) with two values: Health and Status. This provides more intuitive status information.

**List View Improvement**

Improved the list view to support depth, enabling detailed review of database and instance information.

#### Backup/Recovery

**Automatic Reflection of Data File Changes**

Improved recovery so that when a data file is added between the backup and recovery points, it is automatically created during recovery.

**Snapshot Recovery Option Expansion**

Added a full recovery option for snapshot recovery, in addition to the PITR (Point-in-Time Recovery) option.

### Usability Improvements

#### General

**Action Button Adjustment**

Improved readability by grouping previously listed buttons with similar properties.

**Table Column Adjustment**

Added a feature to change the order of table columns or enable and disable them.

#### Dashboard

**Card View Addition**

Added a card view that lets you quickly check important information.

#### Database Creation

**BYOL License Upload Location Change**

Moved the BYOL license file upload from the 'Engine Options' step to the 'Configuration Information Confirmation' step. After completing all settings, you can apply the license that matches the final configuration.

**Maximum vCPU Option Expansion**

Expanded the EC2/VM type options to allow selection of up to 96 vCPUs.

**Automatic Calculation of Redo Log Volume Size**

Changed the Redo Log Volume Size to use an automatically calculated value instead of a value set directly by the user.

**Listener Port Input Location Change**

Simplified the procedure by moving the Listener Port field from the removed 'Network Configuration' step to the additional configuration of the 'Database Configuration' step.

**DB User Creation Simplification**

Simplified the procedure by requiring only the SYS user password instead of creating a new DBA user.

### Deletion Information

#### Database Creation

**Deletion of the 'Network Configuration' Step**

Removed the 'Network Configuration' step because VPC (VNet) and subnet information are unnecessary.
