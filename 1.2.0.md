> ### **Release Highlights**
> 
> - Support for Disaster Recovery (DR) configuration and provision of Auto Failover feature
> - Added storage Auto Scaling feature
> - OwlDB service automatic update
> - Improved dashboard status values and added card view

# New Features

### General

**Dark Mode Support**

Dark mode can now be used according to the user's environment settings, providing visual comfort.

**HTTPS Applied**

Applied HTTPS protocol and domain name to strengthen the security of the service.

### 

### **OwlDB Service Update**

Added a feature to instantly update OwlDB without rebuilding when a new version is released, improving service continuity.



### Database Creation

**Checking Rocky Subscription Status (AWS Only)**

&nbsp;Added a procedure to verify the Rocky subscription status in advance, before entering the database creation page.

**Added the 'Disaster Recovery (hereinafter DR) Configuration' Step**

- In addition to the existing Single and TAC configurations, DR configuration is newly supported.
- You can select whether to use Auto Failover and the level of automation.

**Added the 'Availability Zone (hereinafter AZ) Configuration' Step**

- You can directly select the AZ for the database node to be created.
- When using DR configuration, high availability is supported through Multi-AZ configuration.

**Storage Auto Scaling Settings**

Added a feature that automatically expands storage when storage usage reaches a threshold, supporting stable service operation.

- You can select whether to use the Storage Auto Scaling feature.
- When storage usage reaches the configured threshold, storage is automatically expanded by 10% of the existing capacity.
- To prevent excessive expansion and cost incurrence, you can set a maximum storage capacity limit.

** OS Timezone Settings**

Added a feature to set the OS timezone where the database is installed. (It affects SQL results such as sysdate, systimestamp, etc.)



### Spec Change

**TAC Scale In/Out**

When using TAC configuration, added a feature to manually scale computing resources up/down.

**DR Configuration Change**

- You can add a DR configuration to Single and TAC configurations.
- You can change/remove the DR configuration in Single+DR and TAC+DR configurations.

# **Changes**

## Feature Improvements

### Dashboard

**Status Value Improvement**

Redefined the existing three statuses (operation status, instance status, cluster tool status) into two status values (Health, Status) to provide users with more intuitive status information.

**List View Improvement**

Improved the list view to support Depth, enabling detailed inquiry not only of database information but also instance information.



### Backup/Recovery

**Automatic Reflection of Data File Changes**

Improved the feature so that when a Data File is added between the backup point and the recovery point, the Data File is automatically created during the recovery process.

**Snapshot Recovery Option Expansion**

In addition to the PITR (Point In Time Recovery) option, added a full recovery option for snapshot recovery.



## Usability Improvements

### General

**Action Button Adjustment**

Improved readability by grouping buttons with similar properties among the previously listed buttons.

**Table Column Adjustment**

Added a feature to change the order of columns displayed in the table or enable/disable them.



### Dashboard

**Card View Addition**

Added a card view type that allows you to concisely check only important information, increasing the speed of information comprehension.



### Database Creation

**BYOL License Upload Location Change**

Changed the BYOL license file upload location from the 'Engine Options' step to the 'Configuration Information Confirmation' step, so that after completing all settings, you can accurately apply the license suited to the final configuration following an intuitive flow.

**Maximum vCPU Option Expansion**

Expanded the EC2/VM type options to allow selection of up to 96 vCPU.

**Automatic Calculation of Redo Log Volume Size**

Changed so that the Redo Log Volume Size uses an automatically calculated value instead of being set directly by the user.

**Listener Port Input Location Change**

Simplified the procedure by changing the Listener Port input item from the deleted 'Network Configuration' step to be entered in the additional configuration of the 'Database Configuration' step.

**DB User Creation Simplification**

Simplified the procedure by changing to only entering the password of the SYS user instead of creating a new DBA user.



## Deletion Information

### Database Creation

**Deletion of the 'Network Configuration' Step**

Deleted the 'Network Configuration' step as VPC (VNet) and Subnet information were determined to be unnecessary.
